# Sales Engine: research and live coaching assessment

Reviewed and updated 18 September 2026 against the local repository. This is a code and test assessment, not evidence of improved sales conversion. No live prospects were contacted and no production deployment was performed. Configured-model results and their limits belong in the separate [skill readiness report](skill-readiness.md).

## What is already working

The engine has the right product sequence: offering → campaign strategy → prospect preparation → human call with live cues → reviewed CRM update. The selected contact automatically starts preparation (`src/client/state/useLeadCall.ts:75`). Preparation combines offering, strategy, CRM, prior contact history and web evidence, then validates a concise structured brief (`src/server/research/preparation.ts`). The Ready card leads with the opening and questions, preserves clickable factual citations, and puts hypotheses and unknowns behind More context (`src/client/components/ProspectBrief.tsx`).

A managed campaign cannot start a call using a missing, stale or mismatched brief. The call captures the full preparation, offering, exact opening and generated questions (`src/server/api/calls.ts:100`). The coach receives that snapshot together with recent transcript, qualification state, prior objections and approved claims (`src/server/coach/prompt.ts:51`). Changes to a campaign during the call do not silently change its objective. Tests cover this handoff in `tests/integration/ai-campaigns.test.ts:159`.

The live coach consumes final contact utterances, drops stale model responses and invalid JSON, and has a direct do-not-contact warning path (`src/server/coach/engine.ts`). Calendar actions are proposals requiring separate operator approval. Qualification evidence now matches contact speech only; research, caller assertions and CRM identity fields cannot satisfy that validator. Operator review remains necessary because matching a contact quote does not prove its meaning.

## What this playbook installation changes

`agents/prospect-research/skills.json` selects only `prospect-research-playbook`; `agents/live-coach/skills.json` selects only `live-cold-call-coach`. Existing author packs remain as source references. All six application roles now require exactly one manifest selection at startup. Lower-level legacy discovery remains available but does not bypass application startup validation.

Production loads each selected skill's description and `cheatsheet.md`. It does not read the skill body, chapters, patterns, bibliography, videos or transcripts on each turn. Therefore every procedure needed during preparation or coaching must be in the bounded cheatsheet. A selected pack with no `SKILL.md`, mismatched name or empty cheatsheet raises an error rather than silently running without its procedures (`src/server/agents/loader.ts`).

The preparation input hash now includes the rendered research prompt and output schema. Changes to selected procedures, instructions, schema, or optional `metadata.version` invalidate old briefs for new calls. Existing raw web evidence can still be reused within its own TTL. Inactive reference edits do not force regeneration. Historical call snapshots remain intact (`src/server/research/preparation.ts:15`).

Research instructions request 2–4 questions with exactly one priority question; the interface already selects a required question as the first cue. Live instructions distinguish an ambiguous brush-off from a firm refusal. One respectful clarification is available for ambiguity; a firm refusal ends the pitch, and do-not-contact requires immediate acknowledgement and closure.

## Runtime fixes completed locally

- Contact-only grounding is enforced in the shared evidence matcher used by live qualification and post-call validation/sanitization (`src/server/coach/evidence.ts`). The finalizer's deterministic DNC scan also examines contact speech only (`src/server/review/finalize.ts`). Quote entailment, polarity and criterion relevance remain open.
- A DNC latch stops later contact/chat coaching and discards pending model/calendar work for that live session (`src/server/coach/engine.ts`). It forces the closure warning and removes qualification updates and calendar drafts from the DNC output. The latch is in memory; durable suppression still follows the reviewed CRM write.
- Approval now applies the same per-kind edit allowlist as draft editing and synchronizes stored semantic fields. Skipping a connected-call proposal is rejected (`src/server/review/actions.ts`).
- Model-origin `approve`, `retry_write` and `skip` cannot execute a Sheet write in review chat. The executor replaces their completion claims with an accurate no-write response; an `approve` suggestion containing edits may update the pending draft only. The server's recognized exact operator-command route supplies `source: "operator"`; explicit write endpoints remain separate (`src/server/review/interview.ts`, `src/server/api/review.ts`). This guard covers those three external-write actions, not every model-selected local draft action.
- Approved literal claim spans are removed before the remaining cue is scanned for percentages, currency, guarantees and other flagged proof language (`src/server/coach/claims.ts`). An approved sentence no longer exempts an added invented promise. This remains a lexical check, not semantic verification.

## Evaluation and release plan

1. Keep deterministic contract checks: exact selected pack, missing/empty pack errors, unaffected other agents, brief invalidation after procedure changes, no regeneration after inactive reference edits, and research-to-call snapshot integrity.
2. Create a fixed human-reviewed scenario set: matching company, wrong person with the same name, stale role, sparse evidence, explicit buying trigger, irrelevant news, existing vendor, in-house solution, busy contact, information request, firm refusal, DNC, gatekeeper, follow-up with a different operator, and scheduling without a confirmed time zone. Include at least one adverse case per source of confidence.
3. For research, score identity accuracy, claim support, freshness, relevant problem hypothesis, speakable opening and time/cost to prepare. A fact with a URL but no supporting evidence is a failure. Compare against the same existing briefs, not different prospects.
4. For live coaching, score whether the cue addresses the latest contact words, asks at most one question, respects refusal, avoids unapproved claims, preserves commitments and arrives while useful. Use replayed contact transcripts with a mocked clock for latency/rate-limit tests, then a small controlled operator rehearsal.
5. Run a measured pilot before changing the default based on conversion. Track connect → substantive conversation → mutually agreed next step → meeting held → opportunity. Keep rejection/DNC rates and operator distraction visible. Skill quality is not proven by a model grading its own output.

The latest full local suite passed **232 tests across 45 files**. Type checking and the client build passed; the existing bundle-size warning remains. Focused regressions cover contact-only evidence, DNC races, approval field ownership, connected-call skip rejection, model-origin write blocking, and approved wording plus invented proof. These verify software contracts, not live-model quality or sales conversion.
